# 개발 방향성 (Development Direction)

> 이 문서의 원칙은 [AGENTS.md](../../AGENTS.md) 2장에 "지시사항"으로 그대로 들어가 있다.
> 방향을 바꾸면 두 곳을 함께 고친다.

## 1. 정체성 — 무엇을 지키나

레퍼런스([references](../references/README.md))와 원작자 로그([의도 대조표](../overview/original-intent-audit.md))에서 정리한 이 게임의 핵심:

1. **VS 문법 그대로의 편안한 조작** — 이동만, 공격은 자동. 수동 조준을 넣지 않는다.
2. **질적 성장** — 레벨마다 "수치"가 아니라 "특수 효과"가 붙는다. 진화형은 최종형.
3. **수집형 메타** — 캐릭터 뽑기·각성·돌파·고유 패시브. (VS + 모바일 수집 RPG 혼합이 차별점)
4. **또렷한 레트로 기하 비주얼** — 어두운 월드 위 채도 높은 도형, 잔상·번짐 없음.

이 넷을 바꾸는 작업은 사용자(원작자) 결정 사항이다.

## 2. 작업 원칙

### 2-1. 기술 개입 우선
구조·성능·버그·도구·문서가 기본 범위. 밸런스와 콘텐츠는 요청이 있을 때만.
설명과 구현이 다른 버그는 고치되, 고치면 밸런스가 크게 움직이는 경우 [known-issues](known-issues.md) 에 남기고 확인받는다.

### 2-2. 업데이트가 편해야 한다
| 바꾸고 싶은 것 | 고칠 곳 (한 곳) | 자동으로 따라오는 것 |
|---|---|---|
| 수치 | `src/game/data/config.ts` | 도감, 레벨업 카드, `npm run docs:spec` 수치표 |
| 진화 | `src/game/data/evolutions.ts` | 레벨업 진화 선택지, 도감 진화 탭 |
| 캐릭터·특성·업적·비용 | `src/game/data/progression.ts` | 뽑기 풀, 캐릭터·특성·업적 화면 |
| 무기 추가 | 무기 파일 1개 + `weapons/registry.ts` 1줄 (+타입·config) | WeaponManager, 선택지, 도감 (누락 시 타입 에러) |
| 그림 | `src/assets/icons/<name>.svg` + `assets/icons/map.ts` | 모든 화면·캔버스 |
| 세이브 구조 | `storage.ts` 의 `SAVE_SCHEMA_VERSION` + `MIGRATIONS` | 기존 세이브 자동 변환 |
| 제목·버전 | `src/gameInfo.ts`, `package.json` | 로비 표시, exe 파일 속성 |

배포는 하지 않는 토이 프로젝트이므로 CI·릴리스 자동화는 두지 않는다. 버전은 `package.json` + `CHANGELOG.md` 로만 관리하고, 실행 파일은 `npm run build:exe` 로 다시 만든다.

### 2-3. 하드웨어를 크게 요구하는 렌더링을 피한다
- 목표: 내장 그래픽 노트북(1366×768)에서 60fps.
- 금지: 매 프레임 `shadowBlur`/`filter`, 큰 면적의 매 프레임 그라디언트, WebGL·고해상도 업스케일.
- 장식은 `isLowQuality()` 로 끌 수 있게, 게임 정보는 항상 그린다.
- 근거와 기법: [methodology/canvas-performance.md](../methodology/canvas-performance.md)

### 2-4. AI가 개발하기 편해야 한다
이 저장소는 AI 에이전트가 주로 개발한다(원작자도 Bolt AI로 만들었다).
- **작게 쪼갠 파일, 한 파일 한 책임** — 원작자의 첫 요구도 "토큰 절약을 위한 모듈 구조"였다.
- **폴더마다 README** — 파일을 다 열지 않아도 어디를 고칠지 알 수 있게.
- **검증은 명령 하나** — `npm run check` (타입·린트·헤드리스 시뮬레이션·빌드).
- **주석은 영어로 써도 된다** (기존 한국어 주석은 그대로 둔다). UI 문구는 한국어.
- **생성 가능한 문서는 생성한다** — 수치표는 `docs:spec`.
